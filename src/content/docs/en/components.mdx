# React components and CSS

The package exports pre-wired Better Auth components while leaving layout and application navigation under your control.

## Tailwind CSS setup

Import the package source in your global CSS so Tailwind can detect classes used in the compiled package:

```css
@import "tailwindcss";
@import "@krak-stack/auth/tailwind.css";
```

The components use shadcn design tokens such as `--background`, `--foreground`, `--primary`, `--border`, and `--radius`. Define those variables in `:root` and `.dark`, normally through your existing shadcn theme.

## Provider

Wrap component consumers once near the application root:

```tsx
import { KrakstackAuthProvider } from "@krak-stack/auth/components";

<KrakstackAuthProvider
  locale="en"
  projectId={import.meta.env.VITE_KRAKSTACK_AUTH_PROJECT_ID}
>
  {children}
</KrakstackAuthProvider>;
```

Pass `baseUrl` when the default same-origin endpoint is not appropriate. The provider and components use the owned Effect HttpApi client internally; they do not accept a Better Auth client.

## Account controls

```tsx
import {
  OrganizationSwitcher,
  UserButton,
} from "@krak-stack/auth/components";

<OrganizationSwitcher side="bottom" />
<UserButton signOutRedirect="/" side="bottom" />
```

`OrganizationSwitcher` supports custom menu actions for links into your application's workspace settings. `UserButton` provides account actions and sign-out behavior.

## Forms

The package exports `Signin`, `VerifyEmail`, `ForgotPassword`, `ResetPassword`, and `TwoFactor`. `ResetPassword` renders the email request step without a token and the new-password step with one; `ForgotPassword` remains available when only the email step is needed. Render forms in application-owned routes so URLs, page chrome, and error boundaries remain under your control.

## Authorization guard

`MemberRequired` gates UI on organization membership. Treat it as a presentation guard, not the only authorization layer. Every protected backend endpoint must independently validate the session, organization, and role.

## Hooks, atoms, and contract

Import `useKrakstackAuth`, `useKrakstackAuthProjectConfig`, and `usePermissions` from `@krak-stack/auth/components` inside the provider. For direct Effect state access, use `authSessionAtom`, `authOrganizationsAtom`, and `activeAuthOrganizationAtom` from the same subpath with `@effect/atom-react`. Use the `@krak-stack/auth/auth` HttpApi contract when a custom Effect client is required.
