# Composants React et CSS

Le paquet fournit des composants Better Auth prêts à l'emploi tout en laissant la mise en page et la navigation sous le contrôle de l'application.

## Configuration Tailwind CSS

Importez la source du paquet dans le CSS global afin que Tailwind détecte les classes compilées :

```css
@import "tailwindcss";
@import "@krak-stack/auth/tailwind.css";
```

Les composants utilisent les variables shadcn comme `--background`, `--foreground`, `--primary`, `--border` et `--radius`. Définissez-les dans `:root` et `.dark`, normalement via votre thème shadcn existant.

## Fournisseur

```tsx
import { KrakstackAuthProvider } from "@krak-stack/auth/components";

<KrakstackAuthProvider
  locale="fr"
  projectId={import.meta.env.VITE_KRAKSTACK_AUTH_PROJECT_ID}
>
  {children}
</KrakstackAuthProvider>;
```

Fournissez `baseUrl` si le point de même origine par défaut ne convient pas. Le fournisseur et les composants utilisent en interne le client Effect HttpApi fourni; ils n'acceptent pas de client Better Auth.

## Contrôles de compte

```tsx
import {
  OrganizationSwitcher,
  UserButton,
} from "@krak-stack/auth/components";

<OrganizationSwitcher side="bottom" />
<UserButton signOutRedirect="/" side="bottom" />
```

## Formulaires

Le paquet exporte `Signin`, `VerifyEmail`, `ForgotPassword`, `ResetPassword` et `TwoFactor`. `ResetPassword` affiche la demande par courriel sans jeton et le nouveau mot de passe avec un jeton; `ForgotPassword` reste disponible si seule l'étape du courriel est nécessaire. Affichez les formulaires dans vos propres routes afin de garder le contrôle des URL, métadonnées et limites d'erreur.

## Garde d'autorisation

`MemberRequired` protège la présentation selon l'adhésion à une organisation, mais chaque endpoint backend doit aussi vérifier indépendamment la session, l'organisation et le rôle. Une garde frontend n'est jamais une frontière d'autorisation.

## Hooks, atomes et contrat

Importez `useKrakstackAuth`, `useKrakstackAuthProjectConfig` et `usePermissions` depuis `@krak-stack/auth/components` dans le fournisseur. Pour accéder directement à l'état Effect, utilisez `authSessionAtom`, `authOrganizationsAtom` et `activeAuthOrganizationAtom` depuis le même sous-chemin avec `@effect/atom-react`. Utilisez le contrat HttpApi `@krak-stack/auth/auth` lorsqu'un client Effect personnalisé est nécessaire.
